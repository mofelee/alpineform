# 文档本地化政策

AlpineForm 每一份维护中的 Markdown 文档都必须同时提供英文和简体中文版本。唯一例外是
`AGENTS.md`，因为它是仓库操作元数据，不属于产品、用户或维护者文档。

## 文件命名

- 仓库根目录使用 `<name>.md` 作为英文文件名，使用 `<name>.zh-CN.md` 作为简体中文文件名。
- 仓库根目录以外使用 `<name>.md` 作为英文文件名，使用 `<name>.zh.md` 作为简体中文文件名。
- 一对文件放在同一目录中，使相对资源和相邻文档使用相同的基础路径。

## 翻译要求

- 翻译必须覆盖源文档的完整内容；不接受摘要或只有占位内容的对应文件。
- 命令、CLI 输出、HCL、代码、URL、哈希、版本、兼容性等级、标识符、路径和验证证据必须保留
  完全一致的技术含义。
- 一对文档中的标题级别、围栏代码块及其语言、表格和清单必须保持等价结构。
- 两种语言中的产品行为、运维流程、支持边界和安全保证必须一致。
- 共享行为、支持状态、发布历史或政策发生变化时，必须在同一个变更中更新两种语言。

## 导航

- 每份文档都必须在顶部附近提供醒目的双向语言选择器，并标明当前语言。
- 英文文档默认链接到英文文档；简体中文文档默认链接到简体中文文档。
- 语言选择器是常规情况下唯一允许的跨语言文档链接。
- 仓库内链接使用相对路径，并且必须能够解析，包括标题片段。

## 分发

GoReleaser 归档、curl 安装程序和 `make install` 包含双语根文档及完整的双语 `docs/` 文档树。
分发测试从维护中的源文档树推导预期 Markdown 清单，使新增文档无法被静默遗漏。

## 验证

提交前运行文档门禁：

```bash
make docs-check
```

门禁会验证配对覆盖和命名、语言选择器、结构与技术一致性、翻译覆盖、英文正文、同语言导航、
本地文件和片段，以及发布和安装声明。`make check` 和托管 CI 运行同一个门禁。
